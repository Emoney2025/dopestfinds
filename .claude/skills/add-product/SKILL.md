# Add Product

Adds one real affiliate product to `products.json` without touching the
site's design, layout, styling, search, or category logic. This skill is
the standing implementation of the "PUBLISHING" and "AMAZON" sections of
`CLAUDE.md` — re-read `CLAUDE.md` at the start of every run in case it has
changed, and treat it as the higher authority if anything here ever
conflicts with it.

## 1. Collect and validate inputs

Required, from the user's request:

- **name** — product name
- **url** — the Amazon affiliate URL
- **category** — e.g. Tech, Kitchen, Home, Fitness
- **badge** — e.g. "Hot Find", "Trending", "Best Seller", "Popular"

Optional:

- **image** — either a local file path to an approved image asset, or a
  URL to an image whose promotional/affiliate usage rights are already
  verified (e.g. an Amazon SiteStripe-generated image URL, or an image the
  user explicitly hands you).

Rules while collecting these:

- If `name`, `url`, `category`, or `badge` is missing or ambiguous, **stop
  and ask** — do not guess or invent any of them.
- **Never invent, guess, complete, or "clean up" an affiliate URL.** Use
  only the exact URL the user gives you, or a URL freshly generated by an
  approved Amazon API integration if one is available in this session. If
  neither is available, stop and ask for the URL.
- If an image is supplied, treat it as already approved/rights-verified by
  the user — but never independently fetch, scrape, or substitute an image
  from an Amazon product page, Google Images, or any other third-party
  source. If the user asks you to "find an image" rather than supplying
  one, stop and explain that you can't source Amazon images yourself (see
  `CLAUDE.md` → AMAZON), and ask them to supply or approve one instead.

## 2. Duplicate check

Read `products.json` and check, case-insensitively:

- Is there already a product with the same or a near-identical `name`?
- Is there already a real product (a `url` that isn't the `#` placeholder)
  with the same affiliate `url`?

If either matches, **stop and report the duplicate** — do not add a second
entry, and do not modify the existing one unless the user explicitly asks
you to.

## 3. Decide the image field

- **Approved local file**: copy it into `images/products/` at the repo
  root (create that directory if it doesn't exist yet), named with a
  kebab-case slug of the product name plus its original extension (e.g.
  `bowflex-selecttech-adjustable-dumbbells.jpg`). Set `"image"` to that
  relative path (e.g. `"images/products/bowflex-selecttech-adjustable-dumbbells.jpg"`).
- **Approved image URL**: set `"image"` directly to that URL. Do not
  download/re-host it unless the user asks you to.
- **No approved image**: pick one clear, representative emoji for the
  product (reuse an emoji already used for a similar product in
  `products.json` when one fits) and set `"emoji"` to it. Do not set
  `"image"` in this case.

Only ever set one of `image`/`emoji` on the new entry — `app.js` already
prefers `image` over `emoji` when both would be present, so adding both
would be dead weight, not a fallback.

## 4. Make the smallest possible edit

Append exactly one new object to the end of the `products.json` array,
matching the shape of existing entries:

```json
{
  "name": "<name>",
  "category": "<category>",
  "emoji": "<emoji>",
  "badge": "<badge>",
  "url": "<affiliate url>"
}
```

(substitute `"image": "<path or url>"` for `"emoji"` when an approved
image was supplied). Do not reformat, reorder, or otherwise touch any
existing entry, and do not touch `index.html`, `app.js`, or `styles.css` —
those are the site's existing design/functionality and are out of scope
for a product addition per `CLAUDE.md` → SITE PROTECTION.

## 5. Validate and verify

Run the bundled checker from the repo root:

```
node .claude/skills/add-product/verify.mjs "<exact new product name>"
```

It will:

- Confirm `products.json` is still valid JSON.
- Confirm every entry (old and new) has the required fields.
- Re-run the duplicate check as a safety net.
- Simulate the site's own search and category-filter logic (mirrored from
  `app.js`) to confirm the new product is findable by name/category search
  and that its category filter still returns the expected set, without
  changing the result for any other existing category or search term.

If it reports any failure, fix the JSON and re-run before proceeding —
never push a change that fails this check.

## 6. Branch, commit, push, PR

Follow whatever branch-naming/workflow convention this session's harness
specifies (e.g. a designated branch named in the session's system
instructions, or the "merged PR → restart from latest main" rule if that
designated branch was already merged). If no such convention is active,
create a new branch named `add-product/<kebab-case-product-name>`.

- Commit only `products.json` (and, if applicable, the new file under
  `images/products/`) with a descriptive message naming the product.
- Push with `git push -u origin <branch>`.
- Open a pull request to `main` (check for a PR template first; none
  exists in this repo as of this skill's authoring, but check again since
  templates can be added later). Summarize exactly what was added.

## 7. Report back

Tell the user, plainly:

- The exact product added (name, category, badge, url, and whether it
  used an image or an emoji placeholder, and which one).
- That duplicate checks and `products.json` validation passed.
- That the search/category-filter regression check passed.
- The pull request URL.

Never add more than one product per invocation of this skill — if the
user's request describes multiple products, ask them to run it once per
product (or confirm they want you to repeat the whole flow N times).
